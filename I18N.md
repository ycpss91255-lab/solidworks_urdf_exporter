# Interface languages

The add-in reads `ISldWorks.GetCurrentLanguage()` when it connects, and each
export form reads it when created. `chinese` selects Traditional Chinese
(`zh-TW`). English, unsupported languages (including `chinese-simplified`), a
missing application, and COM language-query failures use English. The host's
numeric culture and UI culture are never changed.

Main part/assembly form captions, dynamic joint-unit labels, PropertyManager
captions/tooltips, menu captions, name-validation messages and the package
destination message use resources. CAD names, URDF identifiers, joint-type
tokens, coordinate-system choices and numeric fields remain unchanged.
Technical exception details and diagnostic logs retain their original text.

Each export form uses one font for all its controls, set before the designer
layout is built (`UiText.CreateFormFont`): Segoe UI 8.5 pt in both languages.
Windows draws the Chinese glyphs through font linking (Microsoft JhengHei UI on
a Traditional Chinese system). Where Segoe UI is missing, Microsoft JhengHei UI
9 pt is used for Chinese and Microsoft Sans Serif 8.25 pt for English.
When the window is drawn at another DPI than the primary screen's (another
monitor in a per-monitor DPI aware SOLIDWORKS), the form rescales its fonts and
layout to that DPI (`UiLayout.ScaleForDpi`).

Resources live in `SW2URDF/UI/Strings.resx` and `Strings.zh-TW.resx`.
Keys are lowercase English captions because ResGen treats keys differing only
by case as duplicates. English display preserves the caller's capitalization.
Unknown keys fall back to the original string. Adding a language requires its
resource file, an explicit native-language mapping, project/installer entries,
and coverage in the tests.

Deploy `zh-TW/SW2URDF.resources.dll` beside `SW2URDF.dll`, keeping the `zh-TW`
subdirectory. The installer script includes this file.

The Tools menu caption (`Export as URDF@&Tools`, parent `工具(&T)` in zh-TW; it must match the real Tools menu caption) and its hints also follow the
language (`UiText.ExportMenuPath`); the item is removed with the same caption it
was added with.

## Tests

All tests are PowerShell scripts under `scripts/` and need no SOLIDWORKS session.
After building `SW2URDF.dll` (with its `zh-TW` satellite beside it):

```powershell
./scripts/test_i18n_catalog.ps1   # resource keys, placeholders, captions (no build needed)
./scripts/test_i18n.ps1           # language detection, fallback, cultures untouched
./scripts/test_i18n_menu.ps1      # Tools menu text, add/remove use the same caption
./scripts/test_i18n_install.ps1   # installer ships the zh-TW satellite
./scripts/test_i18n_layout.ps1    # zh-TW forms add no overlap/clipping at 100/125/150/175%
./scripts/test_form_layout.ps1    # also: one form font per language, rescaling after a monitor DPI change
./scripts/test_i18n_urdf.ps1      # URDF content identical in both languages
```

Not covered offline: the real `AddMenuItem5`/`RemoveMenu` calls against a running
SOLIDWORKS, and the installer's actual output.
